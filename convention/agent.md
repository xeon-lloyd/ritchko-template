# AI Agent Work Guide

## 목적
AI agent가 이 레포에서 작업할 때 반드시 지켜야 하는 행동 기준이다. 목표는 불필요한 변경, 과한 추상화, 숨은 가정, 검증 없는 구현을 줄이는 것이다.

## 기본 태도
- 속도보다 정확성과 작은 변경을 우선한다.
- 사소한 작업은 과하게 의식화하지 말고 판단해서 처리하되, 불확실한 작업은 구현 전에 멈춰서 확인한다.
- 프로젝트별 `AGENTS.md`, 영역별 체크리스트, 전용 컨벤션 문서를 함께 따른다.
- 더 구체적인 영역 규칙이 있으면 그 규칙을 우선하되, 이 문서의 보수적 작업 원칙은 기본값으로 유지한다.

## 1. 생각한 뒤 구현한다
구현 전에 요구사항과 현재 코드의 전제를 먼저 확인한다.

- 확실하지 않은 가정은 명시한다.
- 해석이 여러 개면 조용히 하나를 고르지 말고 선택지를 드러낸다.
- 더 단순한 접근이 있으면 먼저 말한다.
- 요청 방향이 불필요하게 복잡하거나 위험하면 근거를 들어 짚고 넘어간다.
- 이해가 안 되는 부분이 있으면 코드를 쓰기 전에 무엇이 모호한지 말하고 질문한다.

## 2. 단순한 해법을 우선한다
요청을 해결하는 최소한의 코드만 작성한다.

- 요청받지 않은 기능을 추가하지 않는다.
- 한 번만 쓰는 코드를 위해 새 추상화를 만들지 않는다.
- 요구되지 않은 유연성, 설정값, 확장 포인트를 만들지 않는다.
- 실제로 발생할 수 없는 상황을 위한 방어 코드를 늘리지 않는다.
- 코드가 필요 이상으로 길어졌다면 더 짧고 직접적인 구조로 다시 줄인다.

## 3. 수술하듯 변경한다
기존 코드를 수정할 때는 필요한 줄만 건드린다.

- 관련 없는 코드, 주석, 포매팅을 개선하지 않는다.
- 고장 나지 않은 구조를 리팩터링하지 않는다.
- 개인 선호보다 기존 스타일을 맞춘다.
- 관련 없는 죽은 코드나 이상한 구조를 발견하면 삭제하지 말고 언급만 한다.
- 내가 만든 변경 때문에 불필요해진 import, 변수, 함수만 정리한다.
- 변경한 모든 줄은 사용자 요청과 직접 연결되어야 한다.

## 4. 검증 가능한 목표로 작업한다
작업을 시작할 때 성공 기준과 검증 방법을 정한다.

- 버그 수정은 재현 조건과 수정 후 확인 방법을 분리해서 본다.
- validation 추가는 invalid input 확인과 정상 input 영향 여부를 함께 본다.
- refactor는 동작 보존 검증을 포함한다.
- 여러 단계 작업은 짧은 계획을 세우고 각 단계별 확인 방법을 둔다.
- 테스트나 실행 검증이 불가능하면 그 이유와 남은 위험을 명시한다.

예:
```text
1. 입력 검증 추가 -> verify: invalid param이 InputValueNotValid를 반환하는지 확인
2. 기존 정상 흐름 유지 -> verify: 기존 operation 구문 확인과 관련 문서 schema 확인
3. 변경 범위 점검 -> verify: 관련 없는 파일 diff가 없는지 확인
```

## 구현 전 점검
- 요구사항이 한 가지 의미로 확정됐는가?
- 더 단순한 방법이 있는데 복잡한 구조를 만들고 있지 않은가?
- 새 파일, 새 abstraction, 새 설정값이 정말 필요한가?
- 변경 범위가 요청과 직접 연결되는가?
- 검증 방법이 명확한가?

## 구현 후 점검
- 요청하지 않은 기능이나 정리가 들어가지 않았는가?
- 기존 스타일과 파일 배치를 따랐는가?
- 내가 만든 unused code만 제거했는가?
- 가능한 검증을 수행했는가?
- 수행하지 못한 검증이 있으면 이유를 남겼는가?
